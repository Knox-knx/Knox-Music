KNOX MUSIC — Engineering Report: Black-Screen Fix + Smart Playback Cache
1. Black-Screen Root Cause (Phase 1-8 Investigation)
Exact problem: AppImage bundled 10 GStreamer core libraries (libgstreamer-1.0.so.0 etc.) but zero plugin files and no gstreamer-1.0 plugin directory. GStreamer 1.28 then relocated plugin search to <bundled-lib-dir>/gstreamer-1.0 (nonexistent). The AppRun wrapper set GST_PLUGIN_SYSTEM_PATH_1_0 to that same ghost path, resulting in 4 plugins visible instead of 1685 on the host system. When audio playback started, WebKit's autoaudiosink factory returned NULL → g_signal_connect_data on NULL → NULL dereference → WebKitWebProcess SIGSEGV → permanent blank/gray WebView (native window/title bar survived).
Evidence:
- Live Xvfb+xdotool replay: search→play→black screen; WebKitWebProcess gone from ps; log shows no such element factory "autoaudiosink"! → two GLib-GObject-CRITICAL lines
- /proc/<WPID>/maps: web process loaded all libgst* from AppImage bundle; environ showed GST_PLUGIN_SYSTEM_PATH_1_0=<APPDIR>/usr/lib/gstreamer-1.0: (nonexistent)
- Registry debug: using plugin dir <APPDIR>/usr/lib/gstreamer-1.0 (GStreamer 1.28 relocation); plugin count 4 vs host 1685
- Isolated WebKit harness: same AppImage env → WEB_PROCESS_TERMINATED reason=crashed; same harness + host plugin path → PLAY-CALLED|canplaythrough, no crash
- Post-fix live test: 0 crash markers in log; single persistent WebKitWebProcess; audio plays; FullPlayer renders normally
2. Fix Applied
src-tauri/src/gst_env.rs (new): Runs early in main(), before any GTK/WebKit init. If GST_PLUGIN_SYSTEM_PATH_1_0/GST_PLUGIN_SYSTEM_PATH list no usable plugin dir, appends first existing host plugin directory (Debian/Fedora/Arch candidates, KNOX_GST_PLUGIN_DIR override respected). Valid user config never clobbered; plugin-less systems left alone. Web process inherits repaired env at spawn — one fix covers both processes.
src-tauri/src/main.rs (1 line): Calls gst_env::repair_gstreamer_env() before tauri::Builder::default().
Packaging gate (scripts/check-appimage-gst.mjs): New npm run check:appimage that FAILS any AppImage with partial-GST + zero plugins + no repair marker. Pre-fix fails; post-fix passes (RESULT ok).
React hook fixes (Phase 1): Unconditional hooks in SongRow.tsx and FullPlayer.tsx + ErrorBoundary at root/main-content/full-player.
3. Smart Playback Cache Feature (§1-30)
Architecture
- src/cache/ (new module): cacheTypes.ts, cacheStorage.ts, cacheValidator.ts, cacheEviction.ts, smartCache.ts, index.ts
- Dexie table smartcache (v4): keyed by stable song.id, indexed lastPlayedAt + cachedAt
- Strict separation from offline (permanent downloads) and downloads (user-requested)
- Provider capability supportsPlaybackCache + cacheQuality gating
Core Behavior
1. Play request → SmartCache.getPlaybackUrl(song) → cache hit → instant local playback OR cache miss → provider stream + background low-quality cache download
2. Priority: Valid Smart Cache → Authorized provider stream → Failure
3. Never blocks playback: Background download runs fire-and-forget; failures logged; playback continues normally
4. Atomic commits: Bytes stored as Uint8Array; incomplete downloads never persisted (interrupted jobs leave nothing behind)
5. LRU eviction: When budget exceeded, removes least-recently-played entries first; never evicts currently playing track
6. Expiration: Configurable TTL (default 30 days); never affects permanent downloads/playlists/favorites/artwork/lyrics
7. Concurrency dedupe: Single in-flight job per song; duplicate requests reuse same job
Provider Gating
- AirBeats: supportsPlaybackCache: true, cacheQuality: 'low' (per-track audiodownload_allowed)
- Jamendo: supportsPlaybackCache: true, cacheQuality: 'low' (per-track audiodownload_allowed)
- Internet Archive: supportsPlaybackCache: true, cacheQuality: 'low' (rights/license gate)
- FreeTou.se: supportsPlaybackCache: true, cacheQuality: 'low' (per-track gate)
- YouTube Music: supportsPlaybackCache: false — discovery-only, never cached
- Radio: never creates Smart Cache entries (playerMode = "radio")
- Capability-aware: if provider has supportsPlaybackCache: false, cache is skipped
Settings UI (SettingsScreen.tsx → SmartCacheSettings)
- Smart Playback Cache ON/OFF switch
- Cache quality (Low/Medium/High)
- Maximum cache size (500 MB / 1 GB / 2 GB / 5 GB / Unlimited)
- Delete unused cache after (Never / 7 / 30 / 90 days)
- Use cache before streaming ON/OFF
- Stats: Cached songs, Cache used, Available space
- Clear Smart Cache dialog (confirms permanent downloads untouched)
Logging
Structural: SMART_CACHE_HIT, SMART_CACHE_MISS, SMART_CACHE_START, SMART_CACHE_COMPLETE, SMART_CACHE_FAILED, SMART_CACHE_INVALID, SMART_CACHE_EVICT, SMART_CACHE_DISABLED
